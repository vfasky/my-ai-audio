# go-voice macOS app

`go-voice` is the macOS 26+ Apple Silicon desktop host for Go Voice, built with MyGo. Its independent Go module is `github.com/vfasky/my-ai-audio/gui`, and its release bundle identifier is `yz.sh.mygo-go-voice`. Local builds use `go-voice-debug.app` and `yz.sh.mygo-go-voice.debug`; all three helpers also append `.debug` to their identifiers, separating development and release TCC permission records.

The native `go-voice` UI has five pages: device and current speech, vocabulary, speech recognition, AI refinement, and firmware installation, followed by the permissions onboarding; a separate App section of the sidebar holds the General page. It is dark only and follows the macOS 26 layout: a floating Liquid Glass sidebar with inset traffic lights, a toolbar over a soft scroll edge, and grouped-inset sections. Graphite cards, black wells, white primary capsules and a single orange accent reserved for live audio follow the design reference; the FoloToy AI Passport waveform mirrors the newest peaks outward from the centre and falls back to dim dots while idle; the same single well pulses orange during recognition, refinement and insertion. It scans without choosing a device automatically. A user-selected peripheral UUID is persisted for reconnects. The device page shows firmware, handshake state, waveform, RMS/peak, duration, partial transcription, final ASR original, refinement, and frame diagnostics. Audio is neither saved nor replayed.

## Build and validate

Prerequisites: Apple Silicon, macOS 26 or newer, Go 1.27.3, Rust/Cargo (including the `aarch64-apple-darwin` target), Bun (`WAKU_BUN_EXECUTABLE` may select the bundled runtime), and an Xcode SDK containing SpeechAnalyzer and FoundationModels. Go dependencies are pinned in `go.mod` and `go.sum`; Rust dependencies must be pinned in `firmware-helper/Cargo.lock`. gojieba requires CGO and an Xcode C++ compiler. `build.sh` enables CGO and stages the five dictionaries from the pinned module into `Contents/Resources/jieba`; the installed app does not read the build machine's Go module cache. First run `./tools/validate.sh --firmware` from the repository root to produce both verified firmware artifacts.

From the repository root, start the signed debug app with automatic rebuild and restart:

```bash
bun run dev
```

This runs `gui/scripts/dev.sh`; no JavaScript dependencies or `bun install` are needed. Go source and configuration changes rebuild and restart `go-voice-debug.app`. Press Ctrl+C to stop. Swift/Rust helper changes require restarting the command.

For direct build and validation commands:

```bash
cd gui
./scripts/validate.sh
# Or build only:
./scripts/build.sh
# Signed debug session with watch:
./scripts/dev.sh
```

`dev.sh` keeps the firmware and native-helper staging for the session, builds the signed debug app, and launches it through LaunchServices (`open`) so TCC attributes Bluetooth and Speech to go-voice itself. When Go sources, `go.mod`/`go.sum`, `mygo.json`, the icon or entitlements change, it rebuilds; a successful build quits the running app (SIGTERM, so helpers shut down) and starts the new one, while a failed build keeps the running app. App output goes to `gui/build/dev.log`. Quitting the app or Ctrl+C ends the session and removes the staging. Swift or Rust helper changes need a new session. `mygo dev` is not used because it spawns the app as its own child, making the launching terminal TCC-responsible, which terminates BluetoothHelper. `MYGO_SIGN_IDENTITY` selects a signing identity; local builds otherwise use an available Apple Development certificate, falling back to ad hoc if none is available. A stable certificate keeps the debug designated requirement stable across rebuilds; ad-hoc rebuilds can still require new grants. `scripts/stage-debug-project.mjs` stages debug metadata separately, so `mygo.json` retains the release name and identity. Debug builds omit update configuration.

The validation script runs firmware packaging fixture tests, Cargo formatting/tests/Clippy, gofmt, `go test ./...`, `go vet ./...`, and Swift build/tests, then builds the three native helpers and MyGo debug app. It verifies the packaged firmware digest and manifest, nested and outer signatures, and arm64 executables. The result is `gui/build/debug/darwin-arm64/go-voice-debug.app`. Launch the bundled app, rather than `go run`, so native resources and TCC identity resolve correctly. Building does not launch the app, request system permissions, access a FoloToy AI Passport, or touch USB devices.

The same gate is available from the repository root as `./tools/validate.sh --gui`. GUI validation reads `build/FoloToy-AI-Passport.bin` without changing either root firmware artifact. The build temporarily stages `gui/firmware/go-voice-app.bin` and `manifest.json`, packages the directory into `Contents/Resources/firmware`, and removes staging on exit, including build failure. Firmware binaries are not retained in the source tree. `FirmwareHelper.app` ships in `Contents/Resources/native` with its release identity `yz.sh.mygo-go-voice.firmware-helper` (`yz.sh.mygo-go-voice.firmware-helper.debug` locally); inner helpers are signed before the outer app.

## Firmware installation contract

USB installation writes only the bundled application at `0x10000`, with a maximum size of 3 MB and a sector-rounded erase end no later than `0x310000`. Before writing, the helper verifies the image digest/size, ESP32-C3 identity, 8 MB flash and partition-table integrity. It accepts the original five-partition template or the exact measured nine-partition resource layout. Both use the same USB ROM application-write flow without requiring a Recovery bootloader log marker. The [helper contract](firmware-helper/README.md) lists both profiles; unknown layouts are refused. Failed preflight stops before any erase/write and attempts a normal reset. Bootloader, partition table, all resource partitions, device identity (`cardid` at `0x356000`) and permanent Recovery storage (`0x700000`) remain untouched. There is no erase-all operation.

If installation fails, reconnect USB and retry; if the device cannot boot, use its vendor recovery procedure. USB application installation preserves the existing bootloader and Recovery storage; it does not verify or restore a missing UP-key/Recovery implementation. The mini-program/community artifact remains `FoloToy-AI-Passport-full.bin`; the desktop app-only image is not a substitute for it. See the [acceptance record](docs/acceptance.md) for recorded and pending device checks.

## Runtime and privacy

`internal/app` is the only composition layer. UI callbacks emit intentions; background events return through `mygo.RunOnMain`. The coordinator owns session generation, cancellation, early audio buffering and terminal state. Go decodes independent ADPCM frames to 16 kHz, signed 16-bit little-endian mono PCM. By default the Swift subprocess receives that PCM directly and uses SpeechAnalyzer/SpeechTranscriber with volatile results and current vocabulary. It creates a Mac microphone input only for the hotkey described below.

With the online engine chosen on the Speech Recognition page, the app itself streams that PCM to an Alipay MaaS realtime model (`fun-asr-realtime` or `paraformer-realtime-v2`) over a WebSocket to `wss://maas-api.antdigital.com/api-ws/v1/inference` in 100 ms packets, using the DashScope duplex task protocol (run-task, binary audio, finish-task); partial results reach the capsule as they arrive and the final transcript follows task-finished. The non-streaming `qwen3-asr-flash` instead keeps the session's audio in memory and, once the key is released, sends it as one WAV (Base64 data URL) to `https://maas-api.antdigital.com/api/v1/services/aigc/multimodal-generation/generation`; it shows no partial text, and the request is bounded by 45 seconds. SpeechBridge then only claims the session and the target app (`begin`), so refinement and insertion work as with local recognition, and the Speech Recognition grant is not needed for the session. Choosing and saving the online engine explicitly permits sending each session's audio to Alipay MaaS; the vocabulary is not sent and audio is not stored. The start may take up to 4 seconds for connecting while the early audio is buffered; a missing or invalid key, a model the key may not use, a timeout or a failed task ends the session with the reason in Chinese, never falling back to local recognition. The page's Test Connection sends half a second of silence only. The API key is stored only in macOS Keychain (account `asr:alipay-maas`).

The Volcengine Doubao choices follow the [streaming ASR API](https://docs.volcengine.com/docs/DoubaoVoice/LargemodelstreamingautomaticspeechrecognitionAPI) (bidirectional mode, `wss://openspeech.bytedance.com/api/v3/sauc/bigmodel`). The app sends a binary full client request (PCM, 16 kHz, 16-bit, mono), then 100 ms audio packets, and ends with a flagged last packet carrying 100 ms of silence; the text of the reply flagged as last is the final transcript, and earlier replies are previews. Only Streaming ASR 2.0 is offered. The billing plan (hour or concurrency) is chosen by the `X-Api-Resource-Id` the drop-down sets, and must match the plan enabled for the API key; the API key from the new Volcengine speech console is sent as `X-Api-Key` and kept in Keychain under its own account. Legacy APP ID plus Access Token credentials are not supported. No vocabulary or hot words are sent. This was verified against a local protocol peer only, not the live service.

The additional Alibaba Cloud Omni Realtime choice follows the [Omni Realtime interaction protocol](https://help.aliyun.com/zh/model-studio/omni-realtime-interaction-process) and its [input transcription events](https://help.aliyun.com/zh/model-studio/server-events). It defaults to `qwen3.8-omni-flash-realtime`; the page accepts another Omni Realtime model. The address is workspace-specific: choose a region (North China 2 (Beijing) or Singapore) and enter the workspace ID, and the app connects to `wss://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api-ws/v1/realtime` or `wss://{WorkspaceId}.ap-southeast-1.maas.aliyuncs.com/api-ws/v1/realtime`; Custom accepts any other WSS address. Without a workspace there is no default address. Use an API key for that region and workspace. The address must not contain credentials, query parameters or a fragment; the model is added separately. Credentials use a separate Keychain account per Omni endpoint and never reuse the Alipay key. After `session.created`, the app sends `session.update` with 16 kHz PCM input, input transcription enabled and `turn_detection: null`, waits for `session.updated`, then sends Base64 PCM via `input_audio_buffer.append`. Key release sends `input_audio_buffer.commit`. Preview events replace the current sentence with `text + stash`; only the committed item's final input transcript completes dictation. No `response.create` is sent, so assistant replies and generated audio are not used. Finalization is bounded by 15 seconds, and cancellation closes the socket even during a blocked write. Test Connection sends half a second of silence. Live provider behavior and physical-device dictation remain unverified.

BluetoothHelper uses only the Go Voice UUIDs from the [authoritative BLE protocol](../docs/ai-passport-ble-protocol.md). The helper validates MTU and subscriptions before transmitting host_ready, retries acknowledged writes, reconnects with backoff, and shuts down when its parent exits. Both process boundaries have bounded NDJSON and canonical Base64. Audio buffers stay in memory.

The startup model preparation checks/downloads and reserves zh-CN assets, then warms the analyzer. Privacy grants are checked at launch and requested before use, never mid-session: the Permissions page lists Bluetooth, Speech Recognition and Accessibility as required and Automation (System Events) and Microphone (for the hotkey) as optional, shows each state, offers the system request while one can still appear and otherwise opens the matching Privacy & Security pane, and refreshes every two seconds while any is missing. If a required grant is missing once all are reported, the app opens that page; the device page also links to it. A session started without Speech Recognition ends immediately with that reason instead of a start timeout.

During a session a dictation capsule floats at the bottom centre of the display with the pointer, above the Dock, on every Space. The capsule holds a cancel button (Escape is claimed system-wide only while the session runs), a short waveform, a line of fixed width, and a confirm button that skips AI refinement and inserts the ASR original while refinement runs. While you speak and recognition finishes, the line shows the recognized words live: the newest stay at its right edge and slide in smoothly, older ones scroll out to the left under a fade. Before any words it asks you to speak; other phases show the session status (preparing, recognizing, refining). While refinement runs, a preview bubble above the capsule shows the ASR original to be inserted, up to three lines. It is a MyGo panel shown without taking the keyboard, and it hides before any paste so the text reaches the app you dictated into; a cancelled or failed session shows its reason for 1.5 seconds.

The Mac microphone hotkey records without the badge. Hold the chord chosen on the General page (Shift+Option by default; Control+Option, Control+Shift, Command+Option or off) alone for 250 ms anywhere in macOS, speak, and release it to recognize and insert. Pressing any other key, a mouse button or another modifier while holding the chord counts as a shortcut: before 250 ms nothing starts, afterwards the session is cancelled. SpeechBridge watches the chord with a pass-through Core Graphics event tap, which the existing Accessibility grant covers, and opens the default input with AVAudioEngine only while the chord is held; it converts the input to the same 16 kHz 16-bit mono PCM in 20 ms frames, so the session uses the recognition engine, refinement, insertion and capsule of a badge session (an online engine receives this audio as well). Releasing stops the input; recognition finishes when the last frame arrives, or one second after release. A session lasts at most 5 minutes, and an input that sends nothing for 3 seconds ends it. A badge session cannot start during a hotkey session, and disconnecting the badge does not end one. The Microphone grant is optional and listed on the Permissions page; the first hold while it is undetermined shows the system request instead of recording, and a denied grant shows its reason in the capsule. Audio is not stored.

go-voice is a menu-bar app: `LSUIElement` keeps it out of the Dock and the app switcher, and a template icon in the menu bar offers Settings… (Cmd+,, which shows the main window), Check for Updates… (MyGo's signed updater window in release builds; debug builds explain that they do not update) and Quit. Closing the main window hides it; the app keeps running in the menu bar. A power button on the right of the sidebar's connection card also quits, through the same quit sequence; it is disabled while firmware is installing. The General page has an Open at Login switch: it adds go-voice to the login items of the user through MyGo (`SMAppService`, System Settings > General > Login Items) and always shows what the system reports, so turning it off there is reflected too. When macOS asks the user to allow the new login item, the page explains this and links to Login Items until it is allowed. Opened at login, go-voice starts in the menu bar without showing its window, unless a required permission is missing, which shows the permissions page. The setting is not stored in `settings.json`. The icon `gui/resources/tray.png` is derived from the transparent white logo by `"$WAKU_BUN_EXECUTABLE" gui/scripts/generate-tray-icon.mjs` (needs FFmpeg): cropped to the artwork, 36×36 px, black on transparent. Bluetooth, Speech, Apple Events and Microphone usage descriptions are included, and the app and SpeechBridge carry the audio-input entitlement for the hotkey. Text insertion additionally depends on user-granted Accessibility access. Secure Input, missing Accessibility, or an unavailable target leaves the final text on the clipboard. Paste uses System Events with a CGEvent fallback and restores the previous clipboard only after 0.5 seconds if ownership is unchanged.

Apple FoundationModels is the default refinement engine. Disabled, proper-name, light (default) and structured modes are available. Proper-name only corrects vocabulary terms; light corrects vocabulary terms first, then removes fillers that carry no meaning (interjections and hesitation sounds, pause words, false-start repetitions, stray single Latin letters recognized from a hesitation) and fixes punctuation, without rephrasing, reordering or adding anything; structured edits as a proofreader on top of that: it corrects misheard words from context and general knowledge even outside the vocabulary and the candidates (homophones, similar-sounding names, wrong characters, garbled English words), including real words that do not fit the sentence, such as a common verb heard in place of a similar-sounding one (a fast model without thinking may still keep a well-known name heard in place of another, unless the intended name reaches the prompt as a vocabulary term), keeps only the final version of what the speaker took back, fixes broken grammar and sentence breaks with minimal rewording, then adds paragraphs or lists that the content supports, without summarizing, dropping content or adding facts. The fidelity check does not count removed fillers as lost content; for structured mode it accepts more changed wording (at least 55% of the letters kept, at most two fifths new) but still refuses summaries, answers and invented text. `GOVOICE_REFINE_LIVE=1` with `GOVOICE_REFINE_KEY`, `GOVOICE_REFINE_ENDPOINT`, `GOVOICE_REFINE_MODEL` and optionally `GOVOICE_REFINE_API=responses` runs `go test ./internal/refinement -run TestLiveStructuredCorrections`, a billed check of such corrections and of the same words kept where they fit. Every enabled mode, local or remote, also corrects names and terms against the session's vocabulary first (homophones, transliterations, capitalization and spacing) without adding terms that were not spoken. Before calling the model, the app compares pinyin, folding z/zh, c/ch, s/sh, n/l and -n/-ng, and supplies candidate spans plus local gojieba tokens. The model compares the original with all competing terms and keeps ordinary words or uncertain wording rather than preferring a term merely because it is in the vocabulary. Complete-word candidates rank ahead of spans cutting a word; partial matches remain hints requiring stronger context, and correctly spelled vocabulary terms are protected. This also works when Jev is off. Chinese entries in the session vocabulary customize the local dictionary; a changed word set rebuilds it so deleted or renamed entries do not leak into later calls. Remote requests ask the model to turn thinking off (`reasoning_effort`/`reasoning.effort: none`, `thinking: disabled`, `enable_thinking: false`, chat template arguments), fall back to fewer parameters once when a provider refuses them with HTTP 400/422, remember the accepted level per endpoint and model, and drop any `<think>` block from the reply; the fidelity check counts such a replacement as a correction, bounded so that vocabulary terms cannot stand in for the dictation. Failure, timeout, empty output or low character fidelity retains the final ASR original. A local failure never invokes the remote engine. Selecting and saving `remote` explicitly permits sending the final transcript and current vocabulary to the configured HTTPS OpenAI-compatible endpoint; audio is not sent. The settings page labels it as an OpenAI-compatible interface and offers two wire formats: Chat Completions (default) and Responses. An optional stream switch requests the reply as server-sent events and collects the whole text, which is still checked and inserted at once, so it is no faster; it is for services and models that only answer streamed requests, and a stream that fails or stops before its last event is discarded like any failed reply. Optional provider routing fields (only, order and ignore lists, and a switch that forbids providers outside the list) are sent as a top-level provider object for gateways that serve one model from several providers, such as DTMaaS; they are left out when empty. Enter a base endpoint such as `https://provider.example/v1` and a model; the application appends `/chat/completions` or `/responses` accordingly. Responses requests set `store: false` and accept exactly one completed `message` output. Test Connection checks the interface as the page shows it, before saving, with the typed API key or else the saved one: it sends only a fixed sample sentence, never dictation or vocabulary, even while the local engine is selected, and reports success with the refined sample or the likely cause (missing endpoint/model/key, HTTP 401/403/404/429/5xx, timeout, or a reply in the other API format). Save Settings also stores a typed API key in Keychain under the endpoint; Test Connection, Save Settings, Save to Keychain and Delete Credential report their result below the buttons, hidden again once the form changes. API keys are stored only in macOS Keychain using Security.framework. They are not included in settings, logs, test fixtures or `mygo.json`. On the refinement, speech recognition and Jev pages, an empty API key field says when Keychain already holds a key for the drafted endpoint or provider, found without reading it; leaving the field empty keeps that key. The recognition engine drop-down lists each provider once; a provider's models (Fun-ASR, Paraformer and Qwen3-ASR-Flash for Alipay MaaS, the hour and concurrency plans for Doubao) are chosen in its card and share its single API key field, so changing model never asks for the key again. Another provider never receives a typed key, and switching back brings back each provider's typed key, model and drafted Omni address.

Settings and vocabulary are saved under `~/Library/Application Support/MyGo-GoVoice/` with restricted permissions. The vocabulary retains provenance, weight, lock state, creation and usage times, deduplicates normalized terms, and supplies at most 100 contextual strings per session: ranked explicit terms first, then unique replacement targets in unused slots. The Top 100 list feeds Apple local recognition only. Correction freezes the complete vocabulary and unique replacement targets at session start, then retrieves related terms locally on a worker. Matching Chinese terms, literal matches and the Top 100 non-Chinese hints (for transliteration, case and spacing) feed Jev and refinement; the full vocabulary is not sent. More than 256 retrieved terms, 4,096 matching occurrences or 8,000 transcript characters skips both model steps without truncating competitors, retaining local explicit correction. Refinement also declines prompts over 128 KiB. Wrong spellings are not injected; derived targets are not persisted as extra terms. The vocabulary page has four tabs: Terms, Replacements, Jev and Public Dictionaries. Terms lists the terms; Replacements lists rules of an original, a spelling that recognition writes, and its replacement, entered in two fields: live and final recognition results apply them locally, without AI, before the capsule preview, insertion or refinement, the longest original first, again on what a rule wrote next to the dictation, and once more on the refined text. Latin originals ignore case and match whole words only; an original cannot be a term or have two rules. Final correction additionally matches Chinese originals separated by horizontal whitespace at complete dictionary-word boundaries. It preserves punctuation and line breaks, does not cut existing words, and applies only the configured mapping; it does not guess new homophones. This runs on a worker with a vocabulary snapshot, including with both Jev and refinement off. Literal rules take priority; live previews keep literal replacement behavior. The extra pass is skipped for text over 8,000 characters or unavailable dictionaries, retaining literal correction. Replacements typed as aliases of a term by an earlier build move into these rules on load. Export writes the terms (with lock and weight) and the replacements to one JSON file (`"format": "go-voice-vocabulary"`), without usage history; Import merges such a file, or the app's own `vocabulary.json`: it adds what is new, updates the lock, weight and targets of what exists, removes nothing, skips invalid or conflicting entries, and reports the counts. A file of another kind changes nothing. The Jev tab can turn on TypeSafe's Jev model to judge homophone corrections (off by default): when a dictation ends, local gojieba segmentation supplies word boundaries, then Jev uses the complete transcript to compare overlapping candidates and keeping the original in one Choice question per occurrence. Boundaries are hints rather than filters, retaining unfamiliar names split across tokens or merged with neighboring words. Chinese terms of two or more characters are matched by pinyin; correctly spelled vocabulary terms are protected. A replacement is applied only when its choice probability reaches 70%; when keeping the original reaches 70%, refinement is told to preserve it. Uncertain choices stay with refinement. It works with refinement off too. The endpoint and model can be changed: TypeSafe's `https://api.typesafe.ai/v1/systemone` with `jev-latest` by default, an Alipay MaaS preset (`https://maas-api.antdigital.com/v1/systemone`, `jev-1.13`), or any other provider of the System One API; a bare host gets `/v1/systemone`, and an endpoint that is not HTTPS or carries credentials or a query is not saved. Requests contain the complete transcript, local segmentation and matching candidate terms, never audio or unrelated vocabulary; without a match nothing is sent. Each request has at most 24 occurrence groups and 63 alternatives plus the original per group; oversized groups are left to refinement without truncating their alternatives. Text over 8,000 Unicode characters or a request over 128 KiB skips the check without truncating context. After 4 seconds or on failure the step is skipped and the status bar says why. Test Connection sends only a fixed sample, to the endpoint and model the page shows, and lists the probability and outcome of each span. API keys are kept only in the macOS Keychain, one per endpoint (account `vocabulary:typesafe-jev` for TypeSafe, `vocabulary:jev:<endpoint>` for others). Transcripts are shown only for the current session; there is no persistent audio or transcript history.

Public Dictionaries ships a common-word pack of 96,336 Jieba terms and an IT pack of 12,854 THUOCL terms; both default to on, including when loading older settings. Their switches save to settings and apply at the next session. They are read-only background data, separate from personal terms, import/export, the 2,000-term personal limit and Top 100 recognition hints. Public suggestions use exact tone-free phonetic matches on complete token boundaries, keep source and within-source frequency rank, and never protect an ordinary word as a personal name. A cached worker index returns at most eight public alternatives per span and 96 per dictation; personal candidates retain priority in the prompt and Jev question budget. A matched word alone never triggers a local replacement. At least one of refinement or Jev must be enabled. Embedded data is loaded without a network request; only matched candidates reach an explicitly enabled remote model. Source pins, reproducible compilation and the remaining limitations are in [vocabulary evaluation](docs/vocabulary-evaluation.md).

## Releases and updates

Release builds are signed with the team's Developer ID and the hardened runtime, notarized and stapled, and update themselves from signed `go-voice-v*` GitHub releases, checking once a day. `./scripts/release.sh` tests, builds (`./scripts/build.sh --release`), notarizes, verifies, and uploads a draft release; publishing it makes the update available. See [updates, signing, and notarization](docs/updates.md) for keys, setup, the release flow, and update acceptance.
