# Changelog

## Unreleased

- Fix USB firmware installation stopping with `RECOVERY_MARKER_MISSING` on a supported five-partition device. The desktop installer now uses the same bounded ROM application-write flow for both supported layouts, without requiring a bootloader log marker. It retains chip, security, flash-size, image-digest and partition checks, device checksum verification and reset; it preserves the existing bootloader, identity, resources and Recovery storage. The mini-program merged-firmware Recovery contract remains enforced.

- Add a hold-to-talk hotkey to go-voice: hold Shift+Option alone anywhere in macOS to record with the Mac microphone, and release to recognize and insert with the chosen engine, refinement and capsule. The General page chooses another chord or turns it off; any other key pressed while holding cancels, so shortcuts with the same modifiers still work. Microphone is an optional grant on the Permissions page, asked for on first use. Verified by host and Swift tests only; recording and the event tap on a Mac remain unverified.

- Upgrade go-voice from MyGo 0.5.5 to 0.7.3 and require Go 1.27.3. Update release packaging for the new DMG filename. The updater checks about 10 seconds after each launch and then daily, stages verified updates until the app exits, and relaunches through LaunchServices.

- Publish go-voice 0.6.2 with USB support for both the original five-partition template and the measured nine-partition resource layout, and refresh the website download buttons, fallback version labels and release feed.

- Refresh the website download buttons, fallback version labels and release feed for go-voice 0.6.1, the macOS 26 compatibility fix.

- Fix go-voice's macOS 26 build compatibility in 0.6.1: pin C/C++ compilation and linking to the declared minimum instead of inheriting the build machine's newer SDK default. Check the actual arm64 Mach-O minimum for the app and all three helpers, including the update archive. Installation and dictation on a macOS 26 Mac still require device acceptance.

- Prepare `go-voice` 0.6.0 with Doubao streaming recognition, editor-style structured refinement, saved-key hints, provider routing and streaming for refinement, and the new Omni region settings; refresh the website recognition copy and 0.6.0 download links.

- Add two options to the go-voice refinement page for OpenAI-compatible endpoints. Provider routing sends the only, order and ignore lists (and allow_fallbacks false on request) as the top-level provider object that gateways such as DTMaaS use to choose among the providers of one model; nothing is sent while the lists are empty. A stream switch requests server-sent events for both Chat Completions and Responses and collects the whole text, for services and models that only answer streamed requests; the result is still checked and inserted at once, so it is not faster. Streaming was checked against DeepSeek in both formats; routing was checked only by host tests, not against a live DTMaaS.
- Show in go-voice when an API key is already saved: an empty key field on the refinement, speech recognition and Jev pages says Keychain holds one and that leaving the field empty keeps it. The recognition engine drop-down now lists each provider once, and a provider's models are chosen in its card under one shared API key field, so changing between Alipay MaaS or Doubao models never asks for the key again; switching providers restores each one's typed key, model and drafted Omni address. The status pill and the device page now name the chosen online recognition provider instead of always Alipay MaaS.

- Change the go-voice Alibaba Cloud Omni Realtime default model to `qwen3.8-omni-flash-realtime` and replace the free-form endpoint with a region (Beijing or Singapore) plus workspace ID, showing the resulting address; Custom still accepts a full WSS address. The global DashScope address is no longer a default, so existing Omni users must enter a workspace ID once, and a saved model name is kept. Live service behavior remains unverified.

- Add Volcengine Doubao streaming speech recognition to `go-voice` (bidirectional binary WebSocket protocol, `X-Api-Key` authentication) with two resource choices: Streaming ASR 2.0 in the hour and concurrency plans. It shows partial text while you speak and takes the reply flagged as last as the final transcript; its API key has its own Keychain account, Test Connection sends only silence, and failures end the session without switching engines. Choosing it sends each session's audio to Volcengine, without vocabulary. Verified against a local protocol peer only; the live service is unverified.

- Give go-voice structured refinement an editor's authority: it corrects misheard words from context and general knowledge beyond the vocabulary and candidates, including real words that do not fit the sentence, such as a common verb heard in place of a similar-sounding one (a well-known name heard in place of another may still be kept), keeps only what the speaker finally said after taking something back, and smooths broken grammar before adding paragraphs or lists. Its fidelity check accepts these larger edits while still refusing summaries, answers and invented text; names and light modes are unchanged. Live model quality remains unverified.

- Extend gojieba to the `go-voice` vocabulary and replacement pipeline. - Improve `go-voice` Jev vocabulary checks with local gojieba segmentation and complete dictation context. Each occurrence compares all overlapping homophone candidates against keeping the original, applying a replacement or protecting the original only when that choice reaches 70%. Word boundaries are hints, so fragmented unfamiliar names remain candidates. Requests now send the full transcript, segmentation and matching candidates to the selected provider; no audio or unrelated vocabulary is sent. Long requests are skipped without truncating context. Bundle the pinned dictionaries and enable CGO for packaged builds; live model quality remains unverified.

A first key after screen-off can take about 50 ms longer, the first talk after codec sleep may include the analog startup transient, and screen wake waits 120 ms for SLPOUT. Measured current savings remain a device check.

- Add an optional Jev check of homophone corrections to the `go-voice` vocabulary (new Jev tab, off by default). For each span that sounds like a Chinese vocabulary term, TypeSafe's Jev returns the probability that you said the term: likely spans are replaced by code, unlikely ones are kept and AI refinement is told not to change them, and only the uncertain are left to refinement. It works with TypeSafe or any provider of its System One API, such as Alipay MaaS (`jev-1.13`), whose endpoint and model you can enter. It sends the matching spans with some surrounding text and the matching terms to that provider, never audio; it is skipped after 4 seconds or on failure. Each endpoint's API key is kept in Keychain, and Test Connection shows how Jev judges a fixed sample.

- Add replacement rules to the `go-voice` vocabulary, on a Replacements tab next to Terms: enter an original, the spelling recognition writes, and its replacement in two fields, and live and final recognition results apply the rule locally, without AI, before the capsule preview, insertion and refinement. A rule also applies to what another rule wrote next to the dictation, and to the AI-refined text, so the model cannot restore a misrecognition. With refinement off, the replaced text is inserted directly.
